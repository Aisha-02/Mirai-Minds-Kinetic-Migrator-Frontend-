# Kinetic Migrator — Frontend

Next.js UI for Kinetic Migrator: SAP migration staging, validation, comparison reports, and admin rule configuration.

## Stack

- Next.js 16 (App Router) + React 19
- TypeScript
- Tailwind CSS v4 (theme tokens in `app/globals.css`)
- Light professional theme (`color-scheme: light`)

The app talks to the Node API at `NEXT_PUBLIC_API_URL` (default `http://localhost:4000`).

## Setup

```bash
npm install
```

Create `.env.local`:

```
NEXT_PUBLIC_API_URL=http://localhost:4000
```

Start the backend first (see the backend README), then:

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). If port 3000 is taken, Next.js will pick the next free port (for example `3002`).

| Script | Description |
| --- | --- |
| `npm run dev` | Development server |
| `npm run build` | Production build |
| `npm run start` | Serve the production build |
| `npm run lint` | ESLint |

## Auth and roles

Register at `/register` (User or Admin), accept the Terms of Service, then sign in at `/signin`.

| Role | Home | Screens |
| --- | --- | --- |
| `normal_user` | `/staging` | Upload, Display, Validate, Reports |
| `admin` | `/admin` | Rule hub, Analysis / field mapping |

Unauthenticated visits redirect to `/signin`. The wrong role is sent to that role’s home path.

## Pages

| Path | Who | What |
| --- | --- | --- |

## Admin validation selection

On `/admin`, **Validation Selection** lets an admin:

- Toggle predefined checks: trim empty spaces, null keys, duplicate records
- Accept or reject AI-recommended and custom rules (check / X)

**Apply Global Rules** persists the draft (including those toggles and selections) through `POST /api/rules/save`. Cleaning on `/validation` uses that saved set.

## Theme

Color, radius, and shadow tokens live in `app/globals.css` (`@theme inline`). Prefer semantic classes (`bg-surface`, `text-on-surface`, `border-ink/15`) over hardcoded blacks/whites so the light theme stays consistent.

# Mirai Minds — Kinetic Migrator (Frontend)

Next.js 16 App Router UI for the Kinetic Migrator, an SAP data-migration quality platform. It gives two kinds of users their own workspace:

- **Admins** upload a field-metadata Excel, generate AI rule suggestions, write their own custom rules, and publish the rule set for a business object.
- **Normal users** upload preload files to be validated and auto-cleaned, and upload preload/postload pairs to be compared after the load into SAP.

The app is a client-rendered SPA on top of the App Router. Every screen is a client component that talks to the backend over `fetch` with a Bearer token.

---

## Stack

| Piece | Version / choice |
| --- | --- |
| Next.js | 16.3 (App Router) |
| React | 19.2 |
| TypeScript | 5, strict, `@/*` path alias |
| Styling | Tailwind CSS v4 configured through `@theme inline` in `app/globals.css` — there is no `tailwind.config` file |
| Fonts | IBM Plex Sans / Mono via `next/font`, Material Symbols Outlined from the Google CDN |
| Data fetching | Native `fetch` only. No axios, React Query, Redux, or Zustand |

> `AGENTS.md` warns that this is Next.js 16 and its APIs differ from older releases — check `node_modules/next/dist/docs/` before changing routing or config. That block is regenerated by `next dev`, so committing it alongside your work keeps the tree clean.

## Auth and session

| What | Where | Key |
| --- | --- | --- |
| JWT | localStorage | `auth_token` |
| User object | localStorage | `auth_user` |
| Active comparison batch | sessionStorage | `active_batch` |
| Admin workspace pointer | sessionStorage | `admin_workspace` |

`lib/api/http.ts` attaches `Authorization: Bearer <token>` to every request unless the call passes `skipAuth` (register and login). After login, `homePathForRole` sends admins to `/admin` and everyone else to `/staging`.

## State

`context/AdminWorkspaceContext.tsx` is the only React context in the app, and it only wraps `/admin` and `/analysis`. It holds the admin's whole working session:

- `sourceFile`, `sourceSchemaId`, `fileMeta` — the uploaded field-metadata Excel
- `selectedBusinessObject`, `businessObjectOptions`
- `rulesDraft`, `rulesStatus`, `rulesError` — the generated and edited rules
- `schemaMappings`, `mappingStatus`, `mappingError`
- loading flags: `uploadingSchema`, `generatingRules`, `generatingMappings`, `hydrating`

Actions: `registerFile`, `setSelectedBusinessObject`, `generateRules`, `generateMappings`, `setRulesDraft`, `setRulesStatus`, `setRulesError`.

On mount it hydrates from `GET /api/admin/workspace`, restoring cached drafts and mappings keyed by file hash and business object, so a page refresh does not lose work.

Everywhere else, state is local `useState` inside the screen component.

## Design system

`app/globals.css` defines Material Design 3-style semantic tokens through Tailwind v4's `@theme inline`, so components use role names rather than raw colours:

- **Surfaces:** `bg-surface`, `bg-surface-container`, `bg-surface-container-low/high/highest`, `bg-surface-bright`, `bg-surface-dim`
- **Foreground:** `text-on-surface`, `text-on-surface-variant`, `text-on-background`
- **Roles:** `primary`, `secondary`, `tertiary`, `error`, `brand-blue`
- **Typography:** paired utilities such as `font-headline-sm` + `text-headline-sm`, `font-display-lg`, `font-mono-data`, `font-label-caps`
- **Layout:** `sidebar-width` (260px), `assistant-panel-width` (400px), `section-padding`, `container-margin`, `grid-gutter`

Custom utility classes cover the recurring visual patterns: `glass-panel`, `workspace-glass`, `assistant-panel`, `upload-zone`, `drop-zone` (with a `.dragover` state), `glow-input`, and the `animate-slide-progress` / `animate-pulse-icon` / `animate-shimmer-icon` animations.

The app renders dark by default — `<html class="dark">` is set in the root layout.

## User flows

### Sign up and sign in

`/register` creates the account and sends the user to `/signin`. `/signin` stores the JWT and user, then routes by role: admins to `/admin`, normal users to `/staging`.

### Admin: configuring rules (`/admin`)

1. **Upload the schema.** `SourceDataRulesCard` accepts `.xlsx/.xls/.xlsm` and posts it to `/api/admin/source-schema`. The parsed fields render in a table.
2. **Pick a business object** (MM, PO, GL Account, BP, SO). The selection is persisted to the workspace.
3. **Generate rules.** `/api/rules/generate` returns predefined rules (read-only toggles) plus AI suggestions per field.
4. **Add custom rules.** `CustomValidationRuleDialog` collects a field and rule logic and calls the custom-rule endpoints; the local draft updates immediately. Custom rules are shown first with a Custom badge.
5. **Generate schema mapping** (optional) to map source field names to SAP field names, viewable in detail on `/analysis`.
6. **Apply Global Rules** posts the draft to `/api/rules/save`, which becomes the rule set the validation engine uses.

### User: validating a preload file (`/validation`)

1. Drag in a CSV or XLSX preload file.
2. **Execute Cleaning** calls `/api/validation/execute-cleanup`. If the backend cannot confidently detect the business object it returns candidates and the screen shows a selector to retry with an explicit choice.
3. Findings render in `CleaningReport`, grouped by field, in plain language, each labelled with the rule source.
4. Auto-fix runs automatically once a session exists, and the screen reports how many fixes were applied and how many were skipped because a higher-priority rule already handled that field.
5. **Download** fetches a signed URL for the refined file.

### User: comparing preload against postload

1. `/staging` — upload the preload (creating a batch) and the postload (attached to the same batch). The batch id is kept in sessionStorage.
2. `/processing` — `runComparison(batchId)` runs while an overlay animates progress, then the app redirects to `/reports/{batchId}`.
3. `/reports/[batchId]` — file preview alongside `ComparisonReportView`: the AI narrative, metric cards, a filterable issues grid, and a PDF download.
4. `/reports` — paginated history of previous batches.
5. `/preview` — inspect the parsed rows of whichever batch is active.

## Current gaps

Worth knowing before picking up work in this repo:

- The AI assistant panels on the admin, validation, and mapping screens are UI shells. There is no chat backend wired to them yet.
- `/preview` has no `RequireAuth` gate; it relies solely on the sessionStorage batch pointer.
- `PipelineResultsScreen` in `components/pipeline/` has no route — reports render `ComparisonReportView` directly.
- The pipeline step visual on `/staging` is static mock content, not tied to real progress.
- `SideNav` and `AdminSideNav` reference `/workspace-logo.png`, which is not present in `public/`.
- `/` redirects to `/register` rather than `/signin`.
- Several `lib/mock/*` modules (notably `preview.ts` and parts of `pipeline.ts`) are legacy fixtures kept only for copy and fallback styling; the live screens use real API data.
